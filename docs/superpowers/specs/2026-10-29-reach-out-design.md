# Reach out: желаемая частота общения — дизайн

Дата: 2026-10-29
Статус: на согласовании у Макса

Макеты: https://claude.ai/artifact/GFrDFq9RVrP8e4oy3q9xnD (лента, Stats, панель человека с целью и без неё, настройки). Где этот документ и макеты расходятся, правы макеты.

## 1. Зачем

Макс хочет задать для человека желаемую частоту общения: «не реже чем раз в N дней». Плагин показывает, когда пора связаться и когда срок уже прошёл, чтобы не терять людей, которые для него важны.

## 2. Цели, не-цели, анти-цели

Цели:
- задать цель для человека прямо в его заметке, в блоке Person;
- видеть в ленте и на Stats одинаковый блок «Reach out»: с кем пора связаться и с кем срок прошёл;
- видеть статус в заметке человека цветом строки последнего контакта.

Не-цели (MVP, «потом улучшим»):
- разный учёт форматов: сейчас срок закрывает любое взаимодействие, включая переписку;
- уведомления и напоминания вне плагина.

Анти-цели:
- **никакого цвета и никаких списков у человека без цели.** Цвет и «Reach out» появляются только там, где Макс сам поставил цель (решение Макса). Плагин не додумывает, с кем пора общаться;
- новые экраны или элементы сверх макетов.

## 3. Данные

Два свойства во frontmatter заметки человека, рядом с `interactions`:

```yaml
contact_every: 14
heads_up: true
```

- `contact_every` — целое число дней ≥ 1. Нет свойства — у человека нет цели.
- `heads_up` — включена ли для этого человека стадия «пора связаться». Пишется явно (`true` или `false`) в момент, когда у человека появляется цель, со значением «Heads-up for new targets» из настроек, и при каждом нажатии на чекбокс. Поэтому смена этой настройки не трогает людей, у которых цель уже есть. Если свойства нет (заметку правили руками), берётся та же настройка.
- Имена обоих свойств настраиваются в настройках вместе с остальными («Property names»).
- Оба свойства скрыты из обычной панели Properties тем же механизмом, что `interactions`; показываются и правятся только в блоке Person.
- Запись через `processFrontMatter`, как у остальных правок. Очистка поля `contact every` удаляет оба свойства.
- *Моё решение:* значение `contact_every`, которое не целое число ≥ 1 (например `abc` или `0`), считается отсутствием цели. В поле блока оно показывается как есть, чтобы его можно было исправить. Заметку это не ломает.

## 4. Статус

Считается только для человека с целью. `d` — дней с последнего взаимодействия любого формата, считая как «last contact» сейчас (с учётом часа начала дня). `N` — цель, `p` — процент из настроек (по умолчанию 20%).

1. **ok** — ни то ни другое.
2. **soon** («пора связаться», жёлтый) — `heads_up` включён и `N − d ≤ N · p`, при этом `d ≤ N`. Для N = 14 и 20% это дни 12–14.
3. **late** («просрочено», красный) — `d > N`.

*Моё решение:* человек с целью и без единого взаимодействия сразу в статусе late. В списке справа у него «never».

## 5. Экраны

### 5.1 Блок «Reach out» — один компонент для ленты и Stats

- Подпись секции «Reach out» (как подписи секций на Stats).
- Строки — обычная строка человека 60 px: инициал в сером круге, имя, под ним серым «Every N days», справа жирным число дней с последнего контакта («16 days», решение Макса), цветом статуса: красный для late, жёлтый для soon. Для человека без взаимодействий справа «never».
- В блоке только люди в статусах soon и late. Порядок: сначала late, потом soon; внутри — по `d / N` по убыванию, затем по имени.
- Показаны первые пять, ниже «N more», раскрывающее остальных на месте, как сейчас на Stats.
- Тап по строке открывает заметку человека.
- Нет таких людей — блока нет совсем.

### 5.2 Лента

Блок стоит под заголовком «Friends», над днями. Под ним — дни как сейчас, первый день отделён волосяной линией, как дни между собой.

### 5.3 Stats

Блок «Reach out» стоит на месте «Falling behind». «Falling behind» убирается целиком. Блок не зависит от выбранного периода (Week · Month · Year): это состояние на сегодня.

### 5.4 Блок Person в заметке

- Новая строка `contact every` (иконка «repeat»), сразу после `last contact` / `last seen`. Она видна всегда. Без цели поле пустое с плейсхолдером «Empty». Значение правится на месте так же, как редактируемые строки в `HabitBlock` трекера привычек (`editable`): Enter или потеря фокуса сохраняет, Escape отменяет. Показывается как «14 days».
- Строка `heads-up` (иконка «bell») с чекбоксом Obsidian (`metadata-input-checkbox`), как «not at trigger» у привычек. Видна только когда цель задана.
- Цвет получает строка, которая показывает последний контакт: `last contact`, а если последней была встреча, то `last seen`. Жёлтый для soon, красный для late. Подсказка (`title` и `aria-label`) — «6 days ago, every 7 days».
- **Убирается** нынешняя покраска по «usual gap» (`isOverdue`, `markOverdue`). Строка `usual gap` остаётся как факт, без цвета.

### 5.5 Настройки

Новая секция «Reach out»:
- «Heads-up at» — целое число процентов от 1 до 99, по умолчанию 20. Другое значение не сохраняется. Описание говорит, что значит процент, на примере. Выключить стадию для всех нельзя: она выключается у человека.
- «Heads-up for new targets» — какое значение `heads_up` получает человек, когда ему ставят цель; по умолчанию включено.

В «Property names» добавляются «Contact every» и «Heads-up».

## 6. Дизайн-система и правила проекта

- Жёлтый — новый токен статуса в `styles.css` через переменную темы Obsidian (`--color-yellow`), рядом с `--ft-danger`. Красный — существующий `--ft-danger`.
- Новые элементы собираются из существующих частей: строка, круг, подпись секции, «N more». Свой CSS — только для цвета статуса.
- `tests/styles.test.ts` должен проходить без ослабления.
- По `CLAUDE.md` плагина экраны сначала рисуются: до кода добавить в `docs/design/canvas/` доски по макету (лента с Reach out, Stats, Person с целью и без) и раздел в `docs/design/README.md`. Убрать оттуда «Falling behind» и покраску по usual gap.
- Описания в `SettingsTab.ts` и `README.md` обновляются в том же коммите, что и поведение.

## 7. Архитектура

- Домен: цель и статус — чистые функции рядом с `PersonStats` / `Stats`, с тестами на границы (день N — soon, день N+1 — late, `heads_up` выключен, нет взаимодействий, процент 1 и 99, день 0 никогда не soon).
- `fallingBehind` и `isOverdue` удаляются вместе с тестами на них.
- Кодек читает и пишет два новых свойства с настраиваемыми именами. Неизвестные ключи по-прежнему сохраняются как есть.
- Сервис получает операции «задать цель», «убрать цель», «включить/выключить heads-up».

## 8. Что решает строитель

- точные слова описаний в настройках и в README;
- как именно ограничить ввод в поле `contact every` (только цифры или проверка при сохранении);

## 9. Решения, принятые без Макса

- некорректное значение `contact_every` = нет цели (§3);
- человек с целью без взаимодействий — late, справа «never» (§4);
- `heads_up` пишется явно при постановке цели и при каждом нажатии; настройка задаёт его только для новых целей (§3, §5.5);
- процент в настройках — от 1 до 99, без глобального выключения (§5.5);
- очистка цели удаляет и `heads_up` (§3);
- день N ещё soon, а не late (§4).

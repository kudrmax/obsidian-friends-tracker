# Reach out Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A per-person contact target ("contact every N days") with a yellow/red status, shown in one "Reach out" block on the feed and on Stats and in the Person block.

**Architecture:** The target lives on `Person` (domain), is read and written by `PersonCodec` under configurable property names, and its status is a pure function in a new `src/domain/Reach.ts`. `PeopleService` gets the write operations and the list query. One UI function `reachOut()` in `src/ui/reach.ts` draws the block for both views. The old "usual gap" overdue logic (`fallingBehind`, `isOverdue`, `markOverdue`) is removed.

**Tech Stack:** TypeScript, Obsidian API, esbuild, vitest.

**Spec:** `docs/superpowers/specs/2026-10-29-reach-out-design.md`; approved mockups https://claude.ai/artifact/GFrDFq9RVrP8e4oy3q9xnD

## Global Constraints

- Colour and lists only for a person with a target. Nothing about people without one.
- No hardcoded values (Max: «Не хардкодь»): every look value is a `--ft-…` token in `styles.css`; percent and names come from settings; numbers in TS are named constants.
- Property names default to `contact_every` and `heads_up`, configurable under "Property names".
- `contact_every`: whole number ≥ 1; anything else = no target, kept in the note as is and shown in the field as is.
- `heads_up`: written explicitly when a target is first set (value of "Heads-up for new targets") and on every toggle; absent = that setting.
- Clearing the target deletes both properties.
- Status: `late` when `d > N`; `soon` when heads-up on, `d ≤ N` and `N − d ≤ N · p / 100`; else `ok`. No interactions + target = `late`, shown as "never".
- "Heads-up at": whole percent 1–99, default 20. "Heads-up for new targets": default on.
- Row on the right: days since last contact ("16 days"), bold, red for late, yellow for soon. Under the name: "Every N days" ("Every 1 day").
- Order: late then soon; within, by `d / N` descending (never = infinitely late, first), then name. Everyone shown, no cut.
- `SettingsTab.ts` descriptions and `README.md` change in the same commit as the behaviour.
- `tests/styles.test.ts` must pass without loosening.
- Commits: `<summary>` + blank line + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Adding an interaction to a person whose `contact_every` is invalid must not erase or rewrite that value → codec test "keeps an unreadable target as it was".
2. A person's note with `heads_up` absent and a target: toggling the checkbox writes `heads_up` explicitly; adding an interaction does not add it → codec test "leaves heads_up out when it was never written".
3. An interaction dated in the future (another device's clock) makes `d` negative → `d` is clamped to 0, status `ok` (Reach test "a day after today counts as today").
4. Typing "0", "-3", "1.5" or "abc" in the Person block field → nothing is written, the field shows the old value again, a `Notice` says "Contact every takes a whole number of days" (PersonBlock step; service test "refuses a target under one day").
5. A broken person note (can't be decoded) never reaches the Reach out list and doesn't crash it → service test "skips broken notes".

**Interfaces:**
- Produces, in `Person.ts`:
  - `interface Target { readonly every: number; readonly headsUp?: boolean }`
  - `PersonState` gains `readonly target?: Target` and `readonly unreadTarget?: unknown` (the stored value when it isn't a whole number ≥ 1).
  - `person.target(): Target | undefined`, `person.unreadTarget(): unknown`
  - `person.withTarget(every: number, headsUp: boolean): Person` — throws `DomainError("Contact every takes a whole number of days")` unless `Number.isInteger(every) && every >= 1`; keeps an existing explicit `headsUp` when the person already had a target, else uses the argument; clears `unreadTarget`.
  - `person.withoutTarget(): Person` — clears both.
  - `person.withHeadsUp(on: boolean): Person` — throws `DomainError("Set a target first")` without a target.
  - `add`, `replaceAt`, `removeAt` keep target and unreadTarget (fix `with()` to spread state, which it already does).
- Produces, in `Reach.ts`:
  - `type ReachStatus = "ok" | "soon" | "late"`
  - `interface ReachRule { readonly headsUpPercent: number; readonly headsUpForNew: boolean }`
  - `function reachStatus(target: Target, days: number | undefined, rule: ReachRule): ReachStatus` — `headsUp` undefined means `rule.headsUpForNew`.
  - `interface Due { readonly person: Person; readonly status: "soon" | "late"; readonly days: number | undefined; readonly every: number }`
  - `function reachOut(people: readonly Person[], today: LocalDate, rule: ReachRule): Due[]`
- Removes: `fallingBehind`, `Behind` from `Stats.ts`; `isOverdue` from `PersonStats.ts`, with their tests.
